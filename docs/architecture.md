# LinkCli 架构与运行契约

## 模块职责

- `src/registry`：标准 MCP 工具发现、不可变服务版本、风险分类、人工审核、可信项目免审、探活和项目状态。
- `src/gateway`：平台凭据、统一工具清单、工具路由、项目 Token 装配、标准 MCP 服务端和错误映射。
- `src/collection`：解析宿主轮次上下文、生成问题与轮次 HMAC、持久化调用 Outbox、归集轮次、结算规范调用链、重试死信和执行保留期清理。
- `src/analysis`：消费 L2 已结算的完整 Query，按定时批次完成模块路径提取、宽口径聚类、组内场景统计、覆盖缺口识别和 L4 候选 Outbox 写入。
- `src/statistics`：按项目可见性查询调用量、轮次、工具、质量和调用明细，并提供死信重放的控制台入口。
- `src/db`：MySQL 物理模型、事务和查询；`schema.sql` 是绿地数据库真值源。
- `src/auth`：控制台账号、Argon2id 密码和 7 天滑动服务端会话。
- `src/console`：面向 React 控制台的同域查询、权限、差异视图和写操作接口。
- `web`：React + Vite 控制台，生产产物由 Express 同域托管。

## 权限边界

管理接口先校验部署级 `x-admin-api-key`，再读取可信代理提供的平台用户与角色。项目负责人只能登记和修改自己的项目，审核人不能审核自己提交的版本，只有运营者可以永久下线项目。

浏览器不调用 `/admin`，也不保存部署级管理密钥。控制台通过 `/api` 使用 HttpOnly、SameSite Cookie；注册只创建普通成员，项目负责人由项目所有者字段判断，审核员和运营管理员由运营管理员授予。所有写请求校验同源，最终权限始终由服务端执行。

服务绑定到 `0.0.0.0` 或 `::` 时必须配置 `MCP_ALLOWED_HOSTS`，由 MCP HTTP 入口校验 Host 头，避免 DNS rebinding。

外部 Agent 使用平台凭据访问 `/mcp`。第一阶段不配置项目级或工具级授权，因此所有有效平台凭据获得相同的可用工具清单。网关解密项目 Token 后，仅把它作为下游 MCP 认证信息发送；平台凭据、终端用户身份、用户原始问题和内部路由字段不会进入下游业务参数。项目内部数据权限由项目 MCP 决定。统计查询另按项目可见性过滤：普通成员只能查看自己负责项目的调用，审核人和运营者可以查看平台范围；只有运营者可以重放死信。

## 发布与健康

首次登记和每次变更都会生成不可变候选版本。默认进入人工审核；可信项目免审开关默认关闭。批准只代表版本获得发布资格，首次探活成功后才原子切换生效版本。输入输出结构删除或变化被视为高风险，对应工具在审核期间暂停；其他工具继续服务。

草稿阶段的提交时间为空；进入待审核或免审批准时写入 `submitted_at`。七天审核滞留只按该时间计算，不使用草稿创建时间近似。

项目健康状态只持久化 `unknown`、`healthy`、`unhealthy` 和最近探活时间。连续成功、失败计数只保存在当前进程；多实例部署需要保证同一项目的探活归属稳定，或者后续把瞬时计数迁移到共享协调组件。健康结论过期后，项目工具不会继续出现在清单中。

## 调用与采集

公开工具名为 `<projectKey>__<originalName>`。网关在工具定义中加入必填兼容字段 `__linkcli_user_question`，调用前将它从业务参数剥离；项目 MCP 自身不得定义这个保留字段。支持精确归因的宿主应在每次 `tools/call` 的 `_meta` 中提供 `com.tolink.stats/conversation-id` 和 `com.tolink.stats/turn-id`，同一轮用户输入触发的多次工具调用使用相同值；可选的 `com.tolink.stats/turn-sequence` 是聊天内非负序号。没有宿主上下文时，系统按调用凭据、可选传输会话和规范化问题 HMAC 在空闲窗口内推断轮次。连接只用于隔离兼容候选，不被视为轮次真值。

问题缺失、类型错误、空白、超长或含非法控制字符且没有完整宿主轮次上下文时，请求在调用下游前拒绝。短问题、模板问题和问题与参数实体不重合只记录为质量信号，不会阻断业务调用。用户问题允许以明文写入调用表用于统计下钻，但不得进入日志、错误响应或下游业务参数；问题指纹使用独立且稳定的 `COLLECTION_FINGERPRINT_KEY` 计算 HMAC-SHA-256，轮换该密钥前必须迁移仍需归组的指纹与轮次键。

网关在访问下游前写入 `mcp_call_outbox`。该写入失败时返回 `COLLECTION_UNAVAILABLE` 且不调用下游；写入成功后业务工具仍只调用一次，不做自动重试。调用结束后补齐结果、稳定错误分类和耗时；极端情况下完成信息无法写入时保留 `partial/unknown`，不把采集故障转换成会诱发重复副作用的业务重试。后台 Worker 通过租约领取已就绪记录，以事件 UUID 幂等写入 `mcp_call_events`，再根据精确轮次键或兼容候选键更新 `mcp_turns`；兼容模式首次建轮使用数据库级候选键锁，避免多 Worker 把同一轮并行调用拆开。

轮次依次经过 `collecting`、`grace` 和 `finalized`：默认空闲五分钟进入等待，一分钟后定稿，最多一百次调用；等待期出现新调用会回到收集中。精确宿主轮次在定稿后二十四小时内可产生新修订。规范调用链按真实开始时间、持久接收顺序和事件 UUID 排序，时间区间重叠的调用带有同一 `parallelGroup`。结算状态与生命周期、归因质量和单次调用执行结果分别保存；只有 `trusted`、`inferred` 且记录完整的轮次写入分析 Outbox，工具执行成功不等于 Agent 最终答案正确。

调用明细和用户问题默认保留九十天，已投递 L1 Outbox 默认保留七天，死信最多保留九十天；轮次计数和不含参数值的规范调用链长期保留。清理是不可恢复操作。统计入口为 `/api/statistics/summary`、`/api/statistics/tools`、`/api/statistics/turns`、`/api/statistics/calls` 和轮次详情；部署管理入口还提供 `/admin/collection/dead-letters/:id/replay`。

## L3 定时 Query 分析

L3 不消费单次 `CallEnvelope`，也不在用户请求期间实时聚类。它只处理 L2 写入 `mcp_analysis_input` 的完整已结算轮次；输入必须包含稳定 `turn_id`、结算版本、Query、不可逆用户摘要，以及实际 Project、Module、Tool、参数键和结果。零调用或未命中 MCP 的 Query 也必须由 L2 显式写入，否则 L3 无法发现这类需求。

L2 结算成功后先写入 `mcp_analysis_outbox`。后台 Analysis Outbox Worker 通过租约至少一次领取事件，关联 `mcp_turns` 和 `mcp_call_events` 补齐完整事实，再以 `event_id` 和 `turn_id + settlement_version` 双重幂等写入 `mcp_analysis_input`；输入已经写入但确认 Outbox 前进程退出时，重放不会重复计数。候选范围要求使用调用时保存的稳定 `project_id/module_id/tool_id` 快照；当前注册表没有独立 Module 实体，Project 快照只能作为链路测试代理，不能当作正式 Module 边界。

同一 `turn_id` 在批处理前到达更高结算版本时，旧版本被标记为已取代且不参与聚类；轮次已经分析后不接受静默改版，调用方必须发起显式补偿重建，避免旧成员、场景和频次残留在类别中。

调度器默认每 5 分钟读取最多 1000 条未分析输入，并使用 MySQL advisory lock 避免多个 LinkCli 实例同时执行批次。正常输入按有序 `Project/Module` 组合限定候选范围，先用文本指纹去重，再用 Embedding 召回 Top-K 类别，由 `ClusterJudge` 阅读真实代表 Query 决定归类；查询、修改、删除等 Tool 动作只形成组内场景，不作为 Query 类别硬边界。在线路径增量更新质心，已有成员相似度的全量重算只在独立重建任务执行。单条输入失败时只回滚该输入并继续批次，失败记录保留到下一批重试。

候选门槛由 `L3_*` 环境变量配置。没有尝试现有 Skill 且质量达标的类别产生 `new_skill`，明确存在覆盖缺口的类别产生 `expand_skill`，零调用类别产生 `uncovered_demand`。候选与类别状态在同一事务写入 `mcp_l4_candidate_outbox`；数据库幂等键为 `cluster_id + cluster_version + candidate_type`。类别保持 `handed_off` 时不会因样本增加和版本增长重复交付同类型候选；L4 反馈使类别重新进入观察状态后，新版本才可再次交付，不同候选类型不受此抑制。L3 不生成 Skill、不调用业务 MCP，也不主动查询权威业务数据库；回放和数据库反向校验属于 L4。

空库通过 `npm run db:init` 创建全部表；已有数据库在启用调度器前运行 `npm run db:upgrade:analysis`。升级脚本以 `src/db/schema.sql` 为唯一 DDL 来源，并负责将旧的一对一分析表收敛到当前结构。旧 L4 反馈只有在来源类别、Skill 版本、结论和两份验证摘要与验证运行精确等价时才会删除，否则迁移拒绝继续。

## 已知运行限制

- 进程内清单和健康计数不提供跨实例强一致性，数据库生效指针仍是发布真值源。
- 轮次 Worker 当前与网关进程同部署，可靠事实在 MySQL；多实例通过行锁和领取租约协作，但定时任务指标仍需由外部监控采集。
- 零调用和未命中 MCP 的 Query 仍需要宿主提供明确的轮次结束事件；仅靠 `tools/call` 无法发现没有调用行为的需求。
- 当前字符二元组相似度在 50 条真实 MCP Query 测试中产生 50 个单例类别，已确认不能作为正式语义聚类方案。
- `L4_EVENT_ENDPOINT` 未配置时，暂停、恢复、发布、探活失败和七天滞留事件只改变平台状态，不会通知外部 Skill 或运营系统。
- `db:init` 是绿地建表入口；已有 L1 数据库没有自动升级到 L2 表的增量迁移脚本，升级前必须由运维按目标环境单独评审并执行 DDL。
