# MCPSTAT-1-L1 · 服务登记与统一网关实施报告

## 1. 实现结果

LinkCli 现在提供可运行的标准 MCP 聚合服务。项目负责人可以通过受保护的管理 API 登记 Streamable HTTP MCP 服务、生成不可变候选版本并提交审核；提交时单独记录审核计时起点，审核通过且探活成功后，版本才会原子发布。高风险工具定义变化会暂停对应工具，低风险变化不影响旧版本继续服务，项目支持停用、健康恢复和永久下线。

外部 Agent 可以使用平台凭据连接 `/mcp`，获取全部已发布、健康且未暂停的工具，并通过 `<projectKey>__<originalName>` 调用。网关把用户原始问题作为必填归因参数，在访问下游前将其剥离，并携带加密保存的项目 Token 完成下游认证。第一阶段不做项目级或工具级差异授权，也不会自动重试任何工具调用。

调用过程会生成稳定轮次标识，通过有界队列向 L2 异步投递脱敏摘要。工具暂停、恢复、版本发布、探活失败和七天滞留事件可通过 L4 Webhook 外发；相应端点未配置时使用空投递器，不阻塞登记和调用主链路。

### 登记、审核和运行状态

主要实现位置：

- `src/registry/project-service.ts`：登记项目、创建不可变版本、识别重复定义和暂停高风险工具。
- `src/registry/review-service.ts`：提交、并发审核、可信免审、首次探活和按版本号单向原子发布。
- `src/registry/health-monitor.ts`：探活阈值、健康恢复、项目启停下线和滞留告警。
- `src/db/schema.sql`：五张核心业务表及一张工具运行辅助表的 MySQL 绿地 DDL。

### 统一 MCP 网关

主要实现位置：

- `src/gateway/server.ts`：标准 MCP Streamable HTTP 初始化、工具清单和调用入口。
- `src/gateway/auth.ts`：平台令牌签发、摘要校验、过期判断和吊销。
- `src/gateway/catalog.ts`：读取生效清单、过滤不健康或暂停工具并注入原始问题参数。
- `src/gateway/router.ts`：解析路由、解密项目 Token、单次下游调用、健康反馈和 L2 投递。
- `src/collection/envelope.ts`：轮次标识、敏感字段脱敏和正文截断。

## 2. 实际运行方式

1. 运维准备 MySQL 空库和运行密钥，执行 `npm run db:init` 创建 schema，再启动 `npm run dev` 或构建后的 `npm start`。
2. 管理调用携带部署级 Admin API Key、平台用户和角色。项目登记时平台连接下游 MCP 拉取工具定义，连接或协议校验失败不会留下已发布版本。
3. 候选版本默认等待人工审核；运营者明确开启可信免审时可跳过人工结论，但仍需首次探活成功。发布只更新项目生效版本指针，历史版本和审核记录保留。
4. Agent 使用 Bearer 平台令牌访问 `/mcp`。平台令牌只以 SHA-256 摘要落库；项目 Token 使用 AES-256-GCM 密文保存，只在下游调用期间解密。
5. 调用成功或失败都会更新运行时健康判断并尝试投递脱敏过程。下游失败不重试；L2 或 L4 外发失败不改变已经产生的业务结果和状态决定。

## 4. 当前限制与 PR 重点

当前仍存在以下限制：

- 健康连续计数和统一清单缓存属于进程内状态。多实例部署必须保证同一项目的探活归属稳定；数据库中的生效版本指针仍是发布真值源。
- `db:init` 只面向全新空库，没有已有数据库的增量迁移链。
- 未配置 `L2_ENDPOINT` 或 `L4_EVENT_ENDPOINT` 时使用空投递器，对应外部采集或通知不会发生。
- 管理接口假设 `x-platform-user-id` 和 `x-platform-role` 由持有 Admin API Key 的可信代理写入，不应直接暴露给不可信网络。

完整流程测试发现并修复了多项原有偏差：审核事务现在先以 `SELECT ... FOR UPDATE` 锁定候选版本，发布事务锁定版本和项目指针，避免锁竞争被错误返回为 500；项目唯一键冲突被统一转换为业务 `CONFLICT`，退役项目标识复用稳定返回 409；候选版本创建锁定项目行并在事务内回读定义哈希，使并发重复请求稳定幂等；候选探活与当前生效版本的运行健康相互隔离；高风险候选驳回会按其他未决候选重新计算暂停集合；地址不可达使用独立 `DOWNSTREAM_CONNECTION_FAILED` 错误与协议错误区分。

PR 审查时重点确认：

- 已在开发 MySQL 8.0.46 验证 `src/db/schema.sql`、循环外键、JSON、CHECK 和二进制排序规则；后续增量结构变更需补迁移机制，不能重复执行绿地 DDL。
- 使用一个长期运行的企业 MCP 项目继续验证实际项目 Token 权限、工具业务错误语义和超时取消。
- 确认生产反向代理的 Host allow-list、Admin API Key 注入、平台身份头清理和密钥轮换方式。
